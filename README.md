# Замер скорости скачивания

Консольный скрипт на Python: делает 10 запросов подряд к одному адресу, каждый раз дожидается полного ответа, считает среднее время запроса, общий объём и скорость скачивания.

## Запуск

Нужен Python 3.8 или новее. Устанавливать ничего не надо: используется только стандартная библиотека.

```
python3 speedtest.py https://speedtest.hostkey.ru/files/10mb.bin
```

На Windows: `py speedtest.py https://speedtest.hostkey.ru/files/10mb.bin`.

Здесь тестовый файл 10 МБ на сервере Hostkey: 10 запросов скачают около 100 МБ. Лучше брать тяжёлый файл: на маленьком ответе время почти целиком уходит на установку соединения и результат получается заниженным.

Другие адреса, например публичные тестовые файлы Leaseweb ([список серверов](https://kb.leaseweb.com/network/link-speeds)), `http://speedtest.fra1.de.leaseweb.net/10mb.bin` (Франкфурт): на каждом сервере лежат `10mb.bin`, `100mb.bin`, `1000mb.bin`, например `http://speedtest.ams1.nl.leaseweb.net/100mb.bin` (Амстердам). На быстром канале стоит брать `100mb.bin`, но тогда 10 запросов скачают около 1 ГБ.

Параметры (необязательные):

| Параметр | Что делает | По умолчанию |
|---|---|---|
| `-n`, `--count` | число запросов | 10 |
| `--timeout` | сколько секунд ждать данные от сервера | 30 |

## Единицы измерения

- Время запроса - **секунды** (с).
- Объём - **мегабайты** (МБ), 1 МБ = 1 000 000 байт. Точное число байт тоже печатается.
- Скорость - **мегабиты в секунду** (Мбит/с), 1 Мбит/с = 1 000 000 бит/с. В скобках для сравнения дана скорость в **мегабайтах в секунду** (МБ/с); 1 МБ/с = 8 Мбит/с.

Мегабиты выбраны, потому что именно так провайдеры указывают скорость тарифа, и результат можно сравнить с ним напрямую.

## Как считается

- Время одного запроса - от отправки запроса до того, как ответ прочитан целиком (включая установку соединения: у каждого запроса оно новое).
- **Среднее время запроса** = сумма времён всех успешных запросов / их число.
- **Скорость** = весь скачанный объём / суммарное время запросов. Это не среднее из скоростей отдельных запросов: такое среднее завышает результат, когда запросы разной длительности.
- Запросы идут строго по очереди: следующий начинается после полного ответа на предыдущий.
- Если запрос завершился ошибкой (сеть, таймаут, HTTP 404/500), он не попадает в расчёт, ошибка печатается, а число успешных запросов выводится отдельно. Если не удался ни один, скрипт завершается с кодом 1.

Запрос 3: 16.729 с, 10.01 МБ
Запрос 4: 22.831 с, 10.01 МБ
Запрос 5: 0.560 с, 10.01 МБ

## Тесты

```
python3 -m unittest -v
```

Тесты не требуют интернета: они поднимают свой маленький HTTP-сервер на localhost и проверяют, что запросов ровно 10, байты считаются точно, арифметика скорости верна, а ошибки сети не роняют скрипт.

## Ограничения

- Замер включает время установки соединения и TLS-рукопожатия, потому что каждый запрос открывает новое соединение. Это не «чистая» пропускная способность канала.
- `--timeout` ограничивает ожидание данных, а не общее время запроса: очень медленная, но непрерывная загрузка таймаутом не оборвётся.
- Сжатие отключено (`Accept-Encoding: identity`), чтобы считать реальный объём данных, а не сжатый.
